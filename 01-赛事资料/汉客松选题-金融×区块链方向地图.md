# 汉客松选题：金融 × 区块链能做什么、做到什么程度

> 2026-10-02 ｜ 针对你们的组合：**你（金融 + 计算机，全栈 + AI 应用）+ 队友（金融数学，做过银行 AI 项目）**
> 一句话结论：**你们是这场里少见的「金融建模能力」组合，选题必须让这个能力变成硬门槛——不能选一个人人都会做的方向。**

## 零、先定策略：你们不该和工科队比技术

报名材料写着面向「关注人工智能与网络安全的开发者」，现场大概率一半是计算机 / 网安背景。
跟他们比写合约、比系统复杂度，你们必输。

**你们唯一不可替代的东西是：能算。**

别人能做出「一个链上借贷平台」，但做不出「一个风险定价说得通的链上借贷平台」。
别人能做出「一个参数化保险合约」，但算不出「触发概率、基差风险、费率该定多少」。

> **选题的唯一标准：这件事里有没有一个「必须算对」的数？**
> 有 → 你们的主场；没有 → 换一个。

再叠一条：「**删掉区块链，这个产品还成立吗？**」
还成立 → 链是装饰品，赛道结合度那 20% 拿不到；
不成立 → 才对。

## 一、底层工具：区块链在金融里真正能干的 6 件事

判断任何选题，先看它用的是下面哪一条。**用不到任何一条的，直接淘汰。**

| # | 能力 | 金融场景里对应什么 | 演示效果 |
|---|---|---|---|
| 1 | **不可篡改的账本** | 存证、审计追溯、业绩记录防篡改 | 中 |
| 2 | **条件自动执行** | 自动理赔、自动结算、自动分账、强制平仓 | **强** |
| 3 | **可编程的资产** | 份额化、代币化、拆分转让 | 中 |
| 4 | **无需许可的价值转移** | 跨境、小额、机器对机器支付 | 中 |
| 5 | **公开可验证** | 储备金证明、透明度、可信披露 | 中 |
| 6 | **身份与授权凭证** | KYC 复用、授权边界、可携带的信用 | 弱 |

**给你们的口诀**：能选 **#2（条件自动执行）** 就选 #2。
因为它是链最不可替代的能力——**没有区块链，你没法让"合同自己执行"**。而且演示起来最有画面感：「叮，赔付到账了，中间没有任何人点了确认」。

## 二、方向地图：12 个方向，按「金融壁垒 × 技术难度」定位

```
金融壁垒（你们的主场）
   高 │  ⑤票据/应收账款      ①参数化保险        ④供应链金融
      │  ⑥可验证投资业绩      ②链上信用评分
      │                        ③链上衍生品/对赌
      │
   中 │  ⑨ESG/碳追溯        ⑦AI Agent 支付授权   ⑧RWA 代币化
      │  ⑩链上反诈追踪                             ⑪储备金证明
      │
   低 │  ⑫AI 炒币策略                     ⑬跨链结算清算
      └──────────────────────────────────────────────
           低                中                高
                    技术实现难度（别人的主场）
```

**甜点区 = 左上到中上**：金融壁垒高 + 技术难度中。
一共四个方向：**①参数化保险　②链上信用评分　③链上衍生品/对赌　⑤票据与应收账款**。

下面详说，另外挑两个「不在甜点区但值得知道」的。

## 三、推荐 Top 3

### 🥇 第一推荐：参数化保险 + AI 降低基差风险

**一句话定位**：给没有保险公司愿意保的场景（外卖骑手雨天、演唱会退票、小店歇业、农户减产），做一款**触发即赔、不需要报案和定损**的保险——而参数触发的判定由 AI 结合多源数据来做。

**为什么是你们**
- **你有底子**：康衡保那个项目你已经把「核保分级 → 定价 → 给付结构 → 死差益」整条链路想通过一遍，这是别人从零开始的地方。
- **队友是主场**：参数化保险的核心是**触发概率估计 + 基差风险度量 + 费率厘定**——纯金融数学活，现场没人跟你们抢。
- **链不可替代（#2 自动执行）**：不需要信任保险公司会不会赔。条件满足，合约自己打钱。**保单条款从"相信对方"变成"相信代码"**，这是这个产品存在的理由。

**创新点在哪（评审会给分的地方）**
参数化保险最大的硬伤是**基差风险**：参数触发了但你没损失，或者你损失惨重但参数没触发。
**用 AI 解决它**：把卫星图、气象数据、社交媒体文本、甚至商家 POS 流水多源融合，做「真实损失估计」而不是「单点参数判定」——把触发条件从「降雨量 > 50mm」升级成「模型判断该场景确实发生了营业损失」。
这一步同时踩中官方赛题的 **AI 智能体** 和 **可信数据**。

**MVP 边界（40 小时做到这里就够）**
1. 一个险种，只做一个（建议：**外卖骑手雨天配送中断险** 或 **小店台风歇业险**——场景具体、演示有画面）
2. 一个合约：投保 → 触发 → 自动赔付，三个函数
3. 一个预言机数据源：接现成的天气 API（Chainlink 有现成喂价，或自己跑一个定时推送）
4. 一个费率模型：队友算出**一个**费率，附带计算说明（哪怕很简单，但必须能解释）
5. 前端三屏：投保页 / 我的保单 / 赔付记录（赔付那条要能看到链上 tx）

**演示脚本（3 分钟）**
> 「我给这个骑手买了一份雨天险，保费 5 元」→ 现场手动推送一个"触发"数据 → 链上合约自动判定 → **"赔付 50 元已到账，链上可以查这笔 tx"** → 打开区块浏览器给评委看。

**⚠️ 合规红线**：国内保险业务有牌照要求，材料里**必须写成「精算模型与产品原型验证」**，不能宣称在经营保险。康衡保那次你已经处理过这类表述，同一条线。

---

### 🥈 第二推荐：链上信用评分与无抵押借贷

**一句话定位**：把「链上行为 + 链下财务数据」合成一个**可携带、可验证、不可篡改**的信用分，让没有抵押物的人也能借到钱。

**为什么是你们**
- **信用风险建模（PD / LGD / EAD）是标准金融工程内容**，两个人都在主场。
- 队友的银行 AI 项目经验直接对口——银行做的最核心的事之一就是授信评分。
- 你有全栈 + AI 能力，能把模型跑成产品。

**链不可替代（#1 + #6）**
链上信用记录**不可篡改、可跨协议复用**：你在 A 协议按时还款，B 协议能直接认。这是传统征信做不到的（数据孤岛 + 中心化机构可信度问题）。

**MVP 边界**
1. 一个评分模型：输入 5–8 个特征（链上还款次数、钱包年龄、交易对手多样性……），输出 300–850 分。**不用复杂，但要说清每个特征的权重理由**
2. 一个 SBT / 可验证凭证：把分数写成链上凭证
3. 一个极简借贷合约：额度 = f(分数)，演示「还款 → 分数涨 → 额度涨」
4. 前端两屏：我的信用分（带特征归因）/ 借款

**风险**：这个方向黑客松里做的人不少，**必须在「模型有依据」上拉开差距**，否则容易撞车。

---

### 🥉 第三推荐：链上衍生品 / 事件对赌合约

**一句话定位**：让两个主体就一个未来事件（股价、房价、销量、天气）签一份**自动结算、条款不可篡改**的合约。

**为什么是你们**
- **衍生品定价是金融数学的看家本领**（BS 公式、蒙特卡洛、希腊字母）。现场几乎不可能有队伍能把这个算明白。
- 技术实现意外地简单：合约 + 预言机，没有复杂业务逻辑。

**链不可替代（#2）**
对手方风险归零——不需要保证金托管方，不需要担心对方赖账。

**MVP 边界**：一个欧式期权（或最简单的二元期权）+ 一个预言机 + 一份定价说明。

**⚠️ 为什么只排第三**：演示性不如前两个（"两个人打赌"的故事张力弱于"骑手收到赔款"），而且容易被评委当成赌博。**除非你们能把场景落到很实的 B 端需求上**（比如给经销商做价格保护），否则不建议。

### 另外两个值得知道的方向

**④ 供应链金融 / 应收账款融资（壁垒高，技术难度高）**
核心企业的应付账款上链，上游供应商凭此融资。金融壁垒极高（确权、定价、账期），但**40 小时做不完**，而且演示偏企业级、不炸。

**⑦ AI Agent 的支付授权与结算（壁垒中，难度中，但最贴官方赛题）**
当 AI 能自主花钱了，谁给它授权？怎么限额？怎么审计？——官方赛题里明确写了「**身份与权限管理**」。
金融内核是：支付授权、限额风控、对账。
**如果你们想赌「评委更看重赛题契合度」，这个方向值得认真考虑**，而且产品新鲜度最高。代价是金融壁垒不如前三个硬。

## 四、「做到什么程度」—— 40 小时的验收线

这是你问的第二个问题。给你一把尺子，**按 L1→L4 做，L5 有余力再说，L6 一律不做**。

| 层级 | 要求 | 时间占比 | 必须？ |
|---|---|---|---|
| **L1 能跑** | 一条完整路径走得通：打开 → 输入 → AI 处理 → **链上写入** → 界面显示结果 | 45% | ✅ 必须 |
| **L2 能证** | 链上有**至少 1 笔真实交易**，能在区块浏览器打开给评委看 | 10% | ✅ 必须 |
| **L3 能讲** | 3 分钟说清「谁在什么场景下用它、为什么需要链」 | 15% | ✅ 必须 |
| **L4 能演** | **断网也能演示**的兜底模式 | 10% | ✅ 强烈建议 |
| **L5 精致** | 好看的 UI、动效、手机适配 | 20% | ⭕ 有余力再做 |
| **L6 完备** | 多用户体系、完整异常处理、权限管理 | — | ❌ 不要做 |

> **最容易被忽略、也最致命的一条是 L2。**
> 评审「技术完成度」看的是**作品与演示是否完整**。你在台上说「我们用了区块链」没人信，你打开 Etherscan 说「这笔交易就是我们刚触发的赔付」——这一下就成立了。
> **务必保证：演示时屏幕上能出现一个可点击的区块浏览器链接。**

### 链上部分该做到多深？

| 深度 | 做什么 | 建议 |
|---|---|---|
| ★ | 只存证：往合约里写一段数据 | 太浅，只能算"用过链" |
| ★★ | 状态机：合约有 3–5 个函数，能被真实调用改变状态 | 及格线 |
| **★★★** | **自动执行：合约 + 预言机，条件满足自动触发** | **推荐停在这里** |
| ★★★★ | 真实的资产流转：代币转账、托管、分账 | 有时间可加，演示加分 |
| ★★★★★ | ZK、跨链、自己写链 | **绝对不要碰** |

**理由**：★★★ 刚好把链的「不可替代性」体现出来（条件自动执行），而技术风险可控。
★★★★ 只在第一推荐（保险赔付）里值得加——因为"钱真的到账了"比"状态变了"演示效果好得多。

## 五、4 天区块链速成路径（零基础 → 能上台）

**别学区块链，学"用区块链"。** 目标不是理解共识算法，是能部署一个合约并让网页调它。

| 时间 | 做什么 | 产出 |
|---|---|---|
| **10/2 今晚** | 装 MetaMask → 领 Sepolia 测试币 → 在 Etherscan 上看懂一笔交易长什么样 | 能解释「地址 / 交易 / gas / 测试网」 |
| **10/3** | 打开 [Remix](https://remix.ethereum.org)（浏览器里写合约，**零环境配置**）→ 找一个现成的「条件触发转账」合约模板改 → 部署到 Sepolia → 在区块浏览器上看到自己的合约 | **一个部署成功的合约地址** |
| **10/4** | 用 ethers.js 从网页调用你的合约（读状态 + 写状态各一次）→ 把 AI 的输出接到合约入参 | **网页按钮点一下，链上真的发生一笔交易** |
| **10/5** | 串进你们的应用 + 准备离线兜底 + 和队友过演示脚本 | 可演示的 demo |

**必备工具清单**：MetaMask（钱包）、Sepolia 测试网（免费）、Remix（写合约）、ethers.js（前端调链）、Etherscan（给评委看交易）。
**全部零成本，全部有中文文档。**

> **关键心态**：这 4 天你不需要"学会区块链"，只需要**跑通一条路**。跑通了，三天里就照这条路复制。
> 跑不通——10/4 晚上就知道，那时候换方案还来得及。

## 1. 目标口径

v2 只解决一件事：**把"定价"与"投保时刻"从写死的常数，变成按（区域 × 时长 × 险种）可表达的参数，并堵住两个会被套利的口子（知情入场 / 不限购）。**

判定层不动。理由：它是我们最结实的一块，也是"可审计"的落点；改它只有风险没有收益。

## 2. 三处必须先拍板的设计抉择（它们互相影响）

### 抉择①：A2「阈值随窗口缩放」还是 A7「按强度分档」？—— 建议**二选一，不要都做**

两者解决的是同一个问题（P1-2：一个固定阈值配任意窗口，与国标/预警信号分档不对齐），但机制不同：

| | A2 阈值随窗口缩放 | A7 按强度分档（推荐） |
|---|---|---|
| 机制 | `thresholdOf(hours) = 50 × hours / 24` → 24h/48h/72h 分别要 **50/100/150mm**，达标即**全额**赔付 | 用**平均强度**（`during ÷ hours`）定档：≥4.17mm/h→25%、≥8.33→50%、≥16.7→75%、≥33.3→100%（毫米数直接来自国标与四色预警） |
| 好处 | 一行公式，改动最小 | **语义正确**（雨越猛赔越多）、与预警信号**同构**、把路线图里的分档直接落地 |
| 代价 | 只是"把线抬高"，赔付仍是二元 | 赔付额有 4 档 → **B 的定价表与准备金测算要按四档重算**（期望赔付从 `0.01×p` 变成 `Σ tier_k × P(tier_k)`） |
| 对答辩 | 能讲"阈值按国标线性缩放" | 能讲"赔付曲线就是预警信号曲线" ← 更强 |

**我建议 A7**，并把 A2 降级为"如果时间不够就只做 A2"。
**注意**：**不要同时做** —— 两个都做等于要 72h 下 150mm 且强度 ≥4.17mm/h，演示中没有任何城市能触发。

> ⚠️ **无论选哪个，都会改变演示动线**（见 §4）：现在"广州 50mm 正好压线、成都 120mm 满格"这个效果，是建立在 `阈值恒为 50` 之上的。

### 抉择②：A4 冷静期会打断"现场投保、现场理赔"—— 三选一

`t+3` 冷静期一加，**刚买的保单在 3 天内不可理赔**，我们最有力的那条动线（买 → 喂价 → 判定 → 点申请赔付）当场断掉。

| 方案 | 怎么做 | 代价 |
|---|---|---|
| ②-1 **`coolingPeriod` 可配置**（operator 可设，带事件）← **最务实** | 演示/彩排设 **0**，生产设 **3 days** | 削弱说法："operator 能关掉冷却期" —— 必须主动交代，且有链上事件留痕 |
| ②-2 **日历窗口 + 售前截止** | 保单保"某个未来窗口"，且必须窗口开始前买；演示时把窗口设成"买的下一刻" | 窗口逻辑更复杂；状态机多一段 |
| ②-3 **演示用一张已过冷静期的历史保单** | 链上先放一张上周买的保单，现场演示它的理赔 | 现场"买一张新的"仍不能马上赔，动线分裂成两条 |

**我建议 ②-1**（诚实交代 + 事件留痕），并把 ②-2 写在 roadmap 上。

### 抉择③：A6 的自动准备金 —— 循环不可接受，需要"敞口账本"

```solidity
// ❌ 不要这么写：nextPolicyId 一大，gas 就爆
for (uint256 i = 0; i < nextPolicyId; i++) { ... }
```

正解：维护一个**在保敞口累加器**，谁变更谁记账：
- `buyPolicy` → `openExposure += payoutOf(档位)`
- `claim` 赔付成功 → 由 operator 调 `settle(policyId)` 或 `claim` 内直接 `-=`
- **过期未赔**的保单也有敞口 → 需要一个 `settleExpired(uint256[] ids)`（operator 调用，事件留痕）

**代价**：多一个运维动作（每天结算到期敞口），否则 `openExposure` 会虚高、准备金要求偏高。这一条必须写进方案，否则 v2 会带来"准备金只涨不落"的新毛病。

## 3. 逐条接口设计

### A1 保费（区域 × 时长）

```solidity
uint256 public constant MIN_PREMIUM = 0.0002 ether;   // 保费地板（依据：一笔投保链上手续费≈0.00046 ETH）
uint256[3] public HOUR_TIERS = [24, 48, 72];          // 只卖三档（合约层白名单）

mapping(uint8 => mapping(uint256 => uint256)) public premiumGrid;  // regionId => hours => premium

function premiumOf(uint8 regionId, uint256 hours) public view returns (uint256) {
    uint256 p = premiumGrid[regionId][hours];
    if (p == 0) p = aiPremium[regionId];       // 回退：区域基础价
    if (p == 0) p = PREMIUM;                    // 再回退：默认价
    require(p >= MIN_PREMIUM, "premium below floor");
    return p;
}

function hoursAllowed(uint256 h) public pure returns (bool) {
    return h == 24 || h == 48 || h == 72;
}
```

- `buyPolicy(uint8 regionId, uint256 hours)`：`require(hoursAllowed(hours))`、`require(msg.value == premiumOf(regionId, hours))`
- 新增 `setPremiumGrid(uint8 regionId, uint256 hours, uint256 premium, bytes32 reasonHash) external onlyOperator` + 事件 `PremiumSet(regionId, hours, premium, reasonHash)`
- **连带**：`04-脚本/set-premium.js` 从 5 个值变 15 个（已有 `--hours=N` 参数）；定价设计页直接可用；演示页 `hoursInput` 三档已就位，只需把 `premiumOf(region)` 改成 `premiumOf(region, hours)`

### A2 阈值随窗口（若选 A2）

```solidity
uint256 public constant THRESHOLD_PER_24H = 50;              // mm/24h = 国标暴雨下限
function thresholdOf(uint256 hours) public pure returns (uint256) {
    return THRESHOLD_PER_24H * hours / 24;                    // 24→50, 48→100, 72→150
}
// Policy 增字段：uint256 thresholdMm;  buy 时写入 thresholdOf(hours)
// claim / policyStatus / rainfallDuring 三处改读 p.thresholdMm
```

### A7 强度分档（若选 A7，推荐）

```solidity
// 档位由【链上可算的平均强度】决定 —— 不需要 AI 参与，红线那句话继续成立
uint256[4] public TIER_MIN_RATE = [4166, 8333, 16666, 33333];  // mm/h ×10000
uint256[4] public TIER_BPS      = [2500, 5000, 7500, 10000];   // 25/50/75/100%

function tierOf(uint256 duringMm, uint256 hours) public view returns (uint8) {
    uint256 rate = duringMm * 1e4 / hours;   // mm/h ×10000
    if (rate >= TIER_MIN_RATE[3]) return 3;
    if (rate >= TIER_MIN_RATE[2]) return 2;
    if (rate >= TIER_MIN_RATE[1]) return 1;
    if (rate >= TIER_MIN_RATE[0]) return 0;
    return 255;                               // 不达标
}
function payoutOf(uint256 policyId) public view returns (uint256) { ... }
```

- `claim` 里 `during >= THRESHOLD` 换成 `tier != 255`，打款额从 `PAYOUT` 换成 `PAYOUT * TIER_BPS[tier] / 10000`
- `ClaimPaid` 事件已有 `amount` 字段 ✅（不用改事件）
- **必须让 B 重算**：期望赔付 = `Σ P(tier_k) × payout_k`，定价表与准备金测算全部按四档重来

### A3 限购 + 保额封顶

```solidity
uint8   public constant MAX_POLICIES_PER_RIDER = 2;
uint256 public constant MAX_OPEN_EXPOSURE_PER_RIDER = 0.02 ether;  // 2 × 100% 档赔付

// buyPolicy 内：
require(_byRider[msg.sender].length < MAX_POLICIES_PER_RIDER, "too many policies");
require(openExposureOf(msg.sender) + maxPayoutOf(hours) <= MAX_OPEN_EXPOSURE_PER_RIDER, "exposure cap");
```

> 说明：`MAX_OPEN_EXPOSURE_PER_RIDER` 是"按日收入倍数"的可调口径，等 B 给出骑手日均收入的**区间**后填（不猜精确值）。

### A6 准备金自动规则（配合抉择③）

```solidity
uint256 public openExposure;                      // 在保敞口（累加器）
uint256 public constant RESERVE_BPS = 10000;      // 演示用"资本充足口径"= 100% 敞口
function reserveOf() public view returns (uint256) { return openExposure * RESERVE_BPS / 10000; }
// withdrawPool：require(amount <= balance - reserveOf(), "reserve breach")
// setReserve 保留（作为下限的额外加成），但不得低于 reserveOf()
```

### A8 身份（赛期只到白名单）

```solidity
mapping(address => bool) public eligible;         // 被平台/operator 签过的地址
function setEligible(address who, bool ok, bytes32 reasonHash) external onlyOperator;
// buyPolicy：require(eligible[msg.sender], "not an eligible rider")
```
**语义纪律**：只能说「链上验证的是**被平台签过字的地址**」，不能说「验证了这个人是骑手」。生产形态是 B2B2C（平台作投保人）。

## 4. 对演示动线的影响（改之前必须知道）

| 改动 | 现在的效果 | v2 之后 | 应对 |
|---|---|---|---|
| A2 或 A7 | 广州 50mm 压线、成都 120mm 满格（因为阈值恒 50） | **72h 档要 150mm（A2）或强度 ≥4.17mm/h（A7）→ 广州不触发** | 演示默认窗口改成 **24h 档**（= 国标暴雨口径），并重喂一次雨量；看板文案同步 |
| A4 | 现场买 → 现场赔 | 新保单 3 天内不可赔（除非 ②-1 设 0） | 用 ②-1，演示 `coolingPeriod = 0` + 主动交代 |
| A5 | 判定卡不显示源数 | 显示"采信 3 个源" | 直接变强 ✅ |
| A3 | 无感（只买 2 张） | 无感 | 现场只买 2 张 ✅ |
| A7 | 赔 0.01 | 赔 0.0025–0.01（按档） | 讲稿所有"赔 0.01"要改成"最高赔 0.01" |

# 10-金融与定价 · 阅读顺序与归属

> 本目录归**选手 B**（金融/定价/精算）。以下顺序是为了避免"同一个问题两套数字"。

## 阅读顺序

1. **`精算口径.md`** —— **唯一权威口径**。对外材料、PPT、讲稿引用触发概率时，一律用这里的数字。
   - 口径：72 小时窗口（与合约 `MAX_HOURS` 一致）、11 年逐小时真实降雨、任意起点滑动窗口
   - 内含：窗口长度敏感性（6/12/24/48/72/168h）、逐年稳定性、准备金策略、复算方法、交叉验证
2. `精算测算.md` + `backtest_rain.js` —— A 的**独立交叉验证**（日粒度、自然日窗口）。定位是：验证结论 + 提供**历史极值窗口**素材（如武汉 2020-07-05~07 累计 391mm），适合做"历史回放"演示。
   - ⚠️ `精算测算.md` 由 `backtest_rain.js` **自动生成**，不要手改（改了会被下次重跑覆盖）。

## 为什么有两份

两边在不知情的情况下各写了一套实现，结果**互相验证**了：

| 城市 | 精算测算（日粒度 3 天） | 精算口径（小时粒度 72h） | 差异 |
|---|---:|---:|---:|
| 武汉 | 4.88% | 4.756% | 0.12 pp |
| 上海 | 4.66% | 4.557% | 0.10 pp |
| 北京 | 2.12% | 2.265% | 0.15 pp |
| 广州 | 11.70% | 11.524% | 0.18 pp |
| 成都 | 3.59% | 3.719% | 0.13 pp |

这不是矛盾，是**双通道验证**：两套聚合、两个脚本、同一结论（广州越过 10% 保本线）。答辩可主动讲，比单一数字更能顶住追问。

## 复算

```bash
node actuary.js            # 权威口径（首次联网拉数并缓存到 cache/，缓存不入库）
node actuary.js --refresh  # 强制重新拉取
node backtest_rain.js      # A 的独立实现（交叉验证）
```

`cache/` 约 10 MB 原始数据，已 gitignore —— 它是公开 API 的原始响应，一条命令可重建；本地保留是为了现场断网时仍能离线复算。

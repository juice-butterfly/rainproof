## 2. 本轮最强证据：链上现价早已按 R*=60% 执行

**数据工程师发现、主理人独立复算一致**：

| 城市 | 链上现价 | p(72h) | 现价对应 L | **实际赔付率 R** |
|---|---:|---:|---:|---:|
| 武汉 | 0.0008 | 4.756% | 12.5 | **59.5%** |
| 上海 | 0.0008 | 4.557% | 12.5 | **57.0%** |
| 北京 | 0.0004 | 2.265% | 25.0 | **56.6%** |
| 广州 | 0.0020 | 11.524% | 5.0 | **57.6%** |
| 成都 | 0.0007 | 3.719% | 14.3 | **53.1%** |
| | | | **均值** | **56.8%** |

**这条为什么最重要**：

1. 它把「目标赔付率 60%」从**事后解释**变成**链上已执行的事实** —— 五个价格全部落在 53%–60%，不可能是巧合。
2. 它**同时解释了** `PREMIUM = 0.001 ether` 的地位：那只是 `03-合约/RainDeliveryInsurance.sol:20` 的**默认值**，`premiumOf()` 实际读 `aiPremium[regionId]`（`:125-128`）。**「10 倍杠杆」不是我们的定价，是没人用的默认值。**
3. 它给答辩一个**无法被打脸**的句式：不要说「我们的杠杆是 10 倍」，要说「**我们的目标赔付率是 60%，链上现价的实际赔付率是 53%–60%，杠杆由 `L = R*/p` 反解**」。

### 6.1 ★ P0 错误 1：`reserve_mc.js` 的 VaR 取的是**盈利侧**分位（全项目最严重的一处）

**代码级证据**（不是推断）：
- `:129 losses.push(hits * PAYOUT - sim.nPolicies * PREMIUM)` → **正值 = 盈利**
- `:132 losses.sort((a, b) => a - b)` **升序** → `:133 q(0.99)` 取到的是**最赚钱的 1%**
- `:139 P_loss_gt0` → 字段名说"亏损概率"，**实际是「盈利月份占比」**
- `:142 max_eth: losses[losses.length - 1]` → **最赚钱的一个月**

**主理人解析法复算 vs 原脚本（N=200/月）**：E[损益] 与 P(盈利) **逐格吻合**（武汉 −0.10401 / −0.10114，18.14% / 0.181；广州 +0.03260 / +0.02252，44.28% / 0.42533；混合 72h −0.09187 / −0.08906，14.52% / 0.151）→ **证明复算重建正确，错的是字段语义与分位方向**。

**真实的 99% VaR 对五城、两种时长、全部组合一律 = −0.20 ETH = N×PREMIUM**（因为「零赔付」的概率本身就远大于 1%：单城 72h/200 份 武汉 62.15%、上海 63.12%、北京 81.06%、广州 41.58%、成都 76.15%）。**每份预留 = 1.0 倍保费，不是 0.9 倍，更不是 24h 口径的 0。**

### 6.2 ★ P0 错误 2：`P_loss_gt0` 被当成「亏损概率」→ 曾扩散到 7 处对外材料

### 要补的话，找这三类来源（缺一项就不写）

| 类型 | 例子 | 必须能给出 |
|---|---|---|
| 平台方公开报告 | 美团 / 饿了么 的骑手权益或社会责任报告 | 报告名 + 年份 + 发布方 + **数字原文** |
| 官方 / 半官方统计 | 全国总工会相关发布、国家信息中心《中国共享经济发展报告》 | 同上 |
| 权威媒体引用 | 引用上述任一来源的报道 | 同上 + 原文链接 |

### 如果评委问"骑手到底有多少人"，就这么答（不编数字的答法）

> 「我们没有引用未核实的规模数字。而且**我们的论证不依赖规模** —— 这个人群没有保险的原因是**定损成本与赔款同量级**，这是成本结构问题，跟人数多少无关。
>
> 人数决定这门生意能做多大，**不决定它成不成立**。我们证明的是后者。」

这段话不是回避：它把"人多不多"换成"成本结构成不成立"，而成本结构是我们**真能证明**的（见 `产品说明与商业模式.md` §1、§3）。

## 1. 目标用户是谁（定性，不需要数字）

| 特征 | 内容 | 为什么这决定产品形态 |
|---|---|---|
| 身份 | 平台**众包骑手**（非雇员） | 劳动关系模糊 → 法定保障缺位，保险需求真实存在 |
| 计酬 | **按单计酬**，无底薪 | 不出勤 = 零收入 → "暴雨天跑不了单"= 直接收入损失 |
| 收入波动 | 与出勤强绑定，天气是最大外生变量 | 损失可被**天气数据**代理 → 参数化保险成立的前提 |
| 现有保障 | 意外险通常覆盖"人身伤害"，**不覆盖"收入中断"** | 我们填的是**收入损失**这个缺口，不是意外伤害 |

**一句话**：我们保的不是"骑手受伤"，是"骑手今天跑不了单"。

> ⚠️ 这句要小心：我们**不判断骑手是否真的受损**（那需要平台订单数据，见 `产品说明与商业模式.md` §6）。我们判断的是**天气是否达到"显著影响出勤"的水平**。这两句话的分寸要拿准。

## 2. 收入结构：参数化模型（所有输入都标注为假设）

这一节刻意**不写具体数字**，而是给一个**公式化的模型**：任何拿到真实数据的人都能直接代入，而我们不承担"数字来源不明"的风险。

### 2.1 模型

```
单人日收入        R = a × n
   a = 单均收入（元/单）        ← 假设
   n = 日均完成单量（单/日）    ← 假设

暴雨日损失        L = R × q
   q = 当日无法出勤 / 无法接单的比例（0~1）  ← 假设

赔付覆盖度        C = PAYOUT(折算法币) ÷ L
```

### 2.2 三个输入都标为假设，代入时请写清来源

| 符号 | 含义 | 取值 | 状态 |
|---|---|---|---|
| `a` | 单均收入 | `[待补]` | **假设**，需骑手访谈或平台公开口径 |
| `n` | 日均单量 | `[待补]` | **假设**，同上 |
| `q` | 暴雨日停摆比例 | `[待补]` | **假设**，可由"暴雨日单量 vs 平日单量"推 |
| `PAYOUT` | 0.01 ETH | 固定 | 合约 `constant` |
| ETH 法币价 | — | `[待补]` | **假设**，且**必须标注为假设**（币价波动大） |

### 2.3 这个模型能立刻回答的问题

一旦有了 `a`、`n`、`q` 和 ETH 价，就能直接算出一个**非常有说服力的对比**：

> **「一次赔付 0.01 ETH，相当于骑手在暴雨日损失收入的 ＿＿ 倍。」**
>
> （如果接近 1 倍：说明赔付刚好覆盖一天损失，定价基准合理；如果远小于 1：说明赔付太低，需要调 `PAYOUT`。）

**这个"覆盖度 C"是把 `PAYOUT` 从"链上的一个常数"翻译成"骑手能感知的钱"的唯一桥梁** —— 评委问"0.01 ETH 对骑手意味着什么"，就答这个。

### 2.4 我们的定价逻辑与之相容

赔付额是否够，和保费是否够，是两个独立的问题：

- **保费端**（够不够赔）：由 `10-金融与定价/精算口径.md` 的触发概率决定 —— 已算完，广州越线、已加价。
- **赔付端**（够不够用）：由本节的覆盖度 `C` 决定 —— **待补**，需要 `a`/`n`/`q`。

> 两端口径不要混：**保费算的是"我们亏不亏"，赔付算的是"骑手够不够"**。评委可能只问一边，答的时候先分清是哪一边。

## 3. 这个缺口的实际影响与应对

| 维度 | 影响 | 应对 |
|---|---|---|
| 场景价值（20%）中"目标用户与问题是否明确" | 少一个**量化**支点（人数、收入规模） | **论证支点从"人多"换成"成本结构"** —— 成本结构我们能证明（定损成本 ≈ 赔款），人数只影响规模不影响成立性 |
| 评委追问"数据哪来的" | 无来源数字会当场失分 | **主动说明"我们没引用未核实的规模数字"**，并把可复算的精算数字递上去（那是我们真正的一手计算） |
| 材料一致性 | 与 `产品说明与商业模式.md` 不冲突 | 该文档 §1 讲"为什么没人保"用的是成本结构，本节的模型是它的量化补充 |

只有一种情况：**找到可引用来源**，把 §0 的 `[待补]` 换成「数字 + 报告名 + 年份 + 发布方」，并把 §2.2 的四个 `[待补]` 填上（或明确写"访谈/估算，方法如下"）。
